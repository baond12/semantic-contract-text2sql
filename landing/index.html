Ontology-based Semantic Contract Audit

Text2SQL không chỉ cần chạy được SQL. Nó cần đúng ngữ nghĩa.

Dự án này nghiên cứu cách dùng ontology, method contract và semantic audit để kiểm soát quá trình sinh SQL: từ câu hỏi tự nhiên đến truy vấn có thể kiểm chứng.

Audit & Evaluation

Problem

SQL hợp lệ vẫn có thể trả lời sai.

01

Projection mismatch

User hỏi tên ngắn nhưng SQL trả full name.

02

Filter dropped

User hỏi phường nhưng SQL đếm cả xã và đặc khu.

03

Aggregation risk

INNER JOIN có thể làm mất các entity có count bằng 0.

04

Business rule ambiguity

GMV, net sales, refund và order count cần contract riêng.

Approach

Semantic layer có thể kiểm chứng.

{
  "target_class": "Province",
  "operation": "rank",
  "aggregation": {
    "function": "count",
    "target_class": "CommuneLevelUnit"
  },
  "filters": [
    {
      "scope": "child",
      "property": "administrativeUnitType",
      "value": "Phường"
    }
  ],
  "order": "desc",
  "limit": 5
}

Thay vì để LLM sinh SQL tự do, hệ thống chuyển câu hỏi thành structured query intent, sau đó map vào ontology method và SQL template.

Semantic Contract Audit kiểm tra method, parameter, projection, filter, relation, aggregation và unsupported scope trước khi xem kết quả là hợp lệ.

Case Studies

Hai domain để kiểm chứng từng bước.

Vietnamese Admin Units

Domain nhỏ để thiết kế ontology hướng đối tượng, runtime PoC và audit framework.

  • Class, property, relation, method, SQL template.
  • Unsupported relation như vùng - tỉnh.
  • Projection/filter/zero-count audit.

Omnichannel Retail Analytics

Domain bán lẻ đa kênh để thử semantic ambiguity và business rules.

  • 17 bảng, 85 test cases, 70 gold SQL.
  • GMV, net sales, refund, inventory, cohort.
  • Clarify, unsupported, refuse và negative examples.
